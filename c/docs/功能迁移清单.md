审查日期：2026-09-20。来源为 c 的父目录 orders2 本地源码、配置模板和测试。下面 C++ 路径均为拟定去向，尚未创建。未运行旧脚本、访问交易账户或读取真实 .env、订单及日志内容；状态结构依据空模板与读写代码。

旧入口：container_entrypoint.py → main.main → 每轮 getorder.process_once → pto.pto → checkstatus.process_once → pto.inverse_pto；共享 LoggedSession。getorder、pto、checkstatus 使用相同订单文件和锁。available 不在主轮询链内。

## 策略数值基线

开仓固定参数：price_offset="1%"、price_type=3、text="apiv4"、pos_margin_mode="cross"、position_mode="dual_plus"；Open Short 的 is_gte=true，Open Long=false。平仓 reduce_only=true，amount=-当前持仓 size，Close Long 的 is_gte=true，Close Short=false。

目标价格以同一次持仓查询的 entry_price、value、initial_margin、size 计算。size<0 时对 value 取反，否则保持；原始目标价为 entry_price × (1 + initial_margin × 3.1 / 调整后 value)，再按多仓乘 1.01、空仓乘 0.99。最后按来源 finished open 的 price 小数位 ROUND_HALF_UP，保留末尾零。该 price 经状态同步可能已是 trigger_price。不得用二进制浮点近似替代既有精度行为。

现有测试锚点：entry=100、value=1000、margin=10，多仓原始结果 104.131、空仓 95.931；来源 price 为整数时分别取 104、96；HYPE 样例为 83.387。负 value 保留原代码符号行为。非有限数、零 size/value、非正价格、负保证金及舍入为零均需拒绝。

## 旧状态字段映射草案

| 旧字段 | 拟定持久化用途 | 注意事项 |
| --- | --- | --- |
| last timestamp | 信号源消费游标 | 不作为目标完成时间；不同账户/任务如何共享游标需明确 |
| raw orders | 未提交信号及候选操作数据 | 旧数据没有账户、task_id、goal_id、intent_id，不能凭数组位置建立交易归属 |
| pending/finished open/close orders | 订单及迁移来源分类 | finished 只是旧本地分类；导入后仍须整批交易所核对 |
| id | 交易所订单 ID 字符串 | 按账户作用域识别，保留原值 |
| Contract、side | 品种及多空方向、开平操作 | Open/Close 是操作，Long/Short 是任务方向 |
| tag | 原类别及 inverse 来源关联 | pending close orders.inverse <source_id> 建立来源候选关系；来源缺失不得伪造 |
| timestamp | 原始时间值及来源 | 信号记录来自批次；pending 来自创建响应；success 转换未更新时间，不能当成交时间 |
| price、size、value、status | 原始精确数值文本和状态 | price 在 success 时被 trigger_price 替换；size 可能为带符号值；保留原始记录便于展示差异 |

导入先展示摘要，当前实例全部任务停止后整批事务导入；重复完全一致跳过，冲突整批取消并显示差异。账户由迁移上下文绑定，账户、订单 ID 及关键字段核对一致才认定归属；关键字段完整集合在 S5 细化。导入后部分核对失败时整批待核对，全通过后仍保持暂停，用户逐个启动。旧数据不提供新程序客户标识，不能把 text="apiv4" 当作唯一归属或幂等证据。

## 目标完成条件清单（待确认占位）

| 编号 | 原代码条件/行为 | 对目标完成的影响 |
| --- | --- | --- |
| C01 | pto 开仓创建成功后 raw → pending open | 仅子操作提交成功，目标未完成 |
| C02 | checkstatus 详情 status_code=success 且含 trigger_price 后进入 finished open | 旧程序据此开始平仓规划；是否代表真实全部成交尚未核实 |
| C03 | inverse_pto 新平仓创建成功，来源 finished open 被移除 | 只是挂出平仓，不代表目标完成 |
| C04 | checkstatus 平仓 success → finished close，保留 inverse 来源 tag | 这是旧链路可观测的最终记录条件，但没有再查询持仓归零、剩余挂单或成交量 |
| C05 | _has_inverse 命中 pending/finished close 时跳过来源 | 防重复平仓条件，不是独立的目标完成判据 |
| C06 | 详情其他状态直接从 pending 删除；零持仓在平仓规划时报错并保留来源 | 不能将删除或零持仓异常静默认作目标正常完成 |
| C07 | main 永久轮询，getorder 只消费新批次且执行过滤 | 没有显式目标对象/完成事件；新版本目标完成后按策略继续判断，但不能无新证据重复消费旧信号 |

占位结论：`<待确认最终完成判据>`。后续需要将 C04 与真实成交、管理范围内持仓及未决订单的核对结果衔接。此处不擅自新增用户已确认的完成门槛。主动停止撤完归属挂单后结束目标并保留持仓，是需求已明确的另一种结束路径，不等同策略成功平仓。
