## 后续设计约束

- 后台为状态与交易操作的唯一写入者，TUI 通过本机通信发送命令并订阅状态；具体协议在 S4/S5 落实。
- 账户、品种、方向形成任务键；暂停、处理中、等待人工均占用活动名额。
- SQLite 提交防重复 ID 和恢复所需关联成功后才能发送请求；交易请求发出后的崩溃不得自动重发。完整 Intent 和结果执行后保存。
- 父目标与当前子操作分别限制一个未完成项；明确失败暂停父目标，结果未知进入查询核实。
- 旧有“异常后下轮重试”“其他状态直接删除”“HTTP 成功即视为撤单完成”不能直接沿用为新状态机规则。
- 普通日志默认 30 天，其他已指定历史永久保留；恢复必需记录不清理。定时备份默认每小时、24 份，升级备份独立保留 5 份。
- 本地只编写与静态检查，不编译、不执行测试；编译、测试及镜像构建交由 GitHub Actions。后续选定依赖和核实交易所接口时再检查其官方资料，本阶段只记录本地代码事实。
